# Linux setup

Veil intercepts input at the kernel level (evdev) and reads app content through the accessibility bus
(AT-SPI). Both need a one-time setup.

## 1. Input devices (required)

Veil grabs your keyboards and mice and re-emits their events through virtual devices (`/dev/uinput`), so it
can hold a message for a moment while it is checked. Members of the `veil` group get access:

```sh
sudo groupadd -f veil
sudo usermod -aG veil "$USER"
sudo cp packaging/linux/99-veil.rules /etc/udev/rules.d/
sudo cp packaging/linux/modules-load-uinput.conf /etc/modules-load.d/veil-uinput.conf
sudo modprobe uinput
sudo udevadm control --reload && sudo udevadm trigger
```

Log out and back in so the group membership applies. The `.deb`/`.rpm` packages do this for you (except
adding your user to the group).

Security note: access to `/dev/input/event*` lets a program read every keystroke. Only add users that run
Veil, and keep the group otherwise empty.

## 2. Accessibility (recommended)

Veil reads the text of the message you're about to send, and finds Send buttons and file pickers, through
AT-SPI. Veil turns toolkit accessibility on for your session (`org.a11y.Status.IsEnabled`). On GNOME you
can also run:

```sh
gsettings set org.gnome.desktop.interface toolkit-accessibility true
```

Restart Chrome, Chromium-based browsers and Electron apps (Slack, Discord, VS Code…) afterwards so they
expose their content. Without AT-SPI, Veil falls back to what you typed (US layout only).

## 3. Prompts

Veil asks with `zenity` (GNOME and most desktops) or `kdialog` (KDE). Install one of them; without either,
risky actions are cancelled and a notification explains why.

## Session differences

| | X11 | Wayland |
|---|---|---|
| Messages (Enter / Send button) | yes | yes (button detection is approximate: Wayland gives no global pointer position) |
| Paste | yes | yes, if the compositor supports the data-control protocol (wlroots, KDE); otherwise text only via AT-SPI |
| File picker uploads | yes (GTK/Qt/portal choosers, best effort) | yes (best effort) |
| Drag and drop | blocked (drag cancelled with Escape) | **can't be blocked**: Veil warns and asks again before the next send |
| Images (OCR) | not available on Linux | not available on Linux |

Tap-to-click on touchpads is generated by libinput, not the kernel, so a tap on a Send button is not held;
the Enter key and physical clicks are.
